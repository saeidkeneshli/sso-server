# SSO Server

SSO Server is a Spring Boot 3.2.6 API that registers users in Oracle and issues signed JWTs after username and password authentication. It stores passwords as BCrypt hashes and uses stateless Spring Security.

## Run locally

You need JDK 21, Maven, a reachable Oracle database, and an Oracle schema that the application can use.

1. Connect to your development schema and create the `USERS` table if it does not exist. The current JPA entity expects an identity-generated ID.

   ```sql
   CREATE TABLE USERS (
       ID           NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       USERNAME     VARCHAR2(60) NOT NULL UNIQUE,
       PASSWORD     VARCHAR2(60) NOT NULL,
       PHONE_NUMBER VARCHAR2(13) NOT NULL,
       EMAIL        VARCHAR2(60),
       ADDRESS      VARCHAR2(255)
   );
   ```

   The root `create.sql` describes a different schema with a sequence and extra required columns. The script in `document/DB.sql` starts by dropping the users table. Use the definition above for a fresh schema. The application exports schema SQL by default and expects the table to already exist.

2. From the project root, set the connection details and signing key. This PowerShell example prompts for the database password and generates a local signing key. Reuse the same signing key across restarts if existing tokens need to remain valid.

   ```powershell
   $env:SPRING_DATASOURCE_URL = 'jdbc:oracle:thin:@//localhost:1521/XEPDB1'
   $env:SPRING_DATASOURCE_USERNAME = 'SSO'
   $env:SPRING_DATASOURCE_PASSWORD = Read-Host 'Oracle password'
   $key = New-Object byte[] 32
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $rng.GetBytes($key)
   $rng.Dispose()
   $env:APP_JWTSECRET = [Convert]::ToBase64String($key)
   ```

   Replace the host, service name, and username with your Oracle settings. The signing key must be at least 32 bytes. The server uses the configured string directly as key material.

3. Start the application.

   ```powershell
   mvn -Pdev spring-boot:run '-Dspring-boot.run.arguments=--spring.jpa.properties.jakarta.persistence.schema-generation.scripts.action=none'
   ```

   The launch argument disables schema export so startup leaves the checked-in SQL file alone. The default port is `8001` and can be changed with `SERVER_PORT`. Tokens expire after seven days by default. Set `APP_JWTEXPIRATIONINMS` to override the lifetime in milliseconds.

## Run with Docker Compose

From the project root, run `docker compose up --build` to build and start the server with the `prod` profile by default. Compose publishes the API on port `8001`.

To select a different profile, set `SPRING_PROFILE` in PowerShell before building:

```powershell
$env:SPRING_PROFILE = 'dev'
docker compose up --build
```

Supported values are `dev`, `test`, and `prod`. Compose passes the selection to Maven at build time. Maven packages the selected profile's YAML and sets it as the active Spring profile in the JAR. Use `--build` whenever you switch profiles.

Compose runs the application container. The Oracle database configured for the selected profile must be reachable from that container, and its schema must already contain the `USERS` table.

## API

With the server running, open [Swagger UI](http://localhost:8001/swagger-ui/index.html) or fetch the [OpenAPI JSON](http://localhost:8001/v3/api-docs).

### Register a user

Send `POST /auth/register` with a JSON body. Supply `username`, a nonblank `password`, and `phoneNumber`. The `email` and `address` fields are optional.

```powershell
$registration = @{
    username = 'demo-user'
    password = 'local-demo-password'
    phoneNumber = '5550100123'
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Uri 'http://localhost:8001/auth/register' `
    -ContentType 'application/json' -Body $registration
```

A successful registration returns HTTP 200 with `accepted: true`, the username, phone number, and address. If the username already exists, the API returns HTTP 409 with `accepted: false`.

### Log in and use the token

Send `POST /auth/login` with HTTP Basic credentials. The following command prompts for the password used during registration.

```powershell
curl.exe --request POST --user demo-user http://localhost:8001/auth/login
```

A successful login returns HTTP 200 with `accessToken` and `tokenType` set to `Bearer`. A missing Basic authorization header returns HTTP 400. Send `Authorization: Bearer <accessToken>` on protected requests. The default security configuration allows anonymous access to `/auth/**` and the Swagger/OpenAPI paths and requires authentication for other paths. Use HTTPS when sending credentials or tokens outside local development.

## Build

```powershell
mvn -Pprod clean verify
java -jar target/sso-server-1.0-SNAPSHOT.jar --spring.jpa.properties.jakarta.persistence.schema-generation.scripts.action=none
```

Choose `-Pdev`, `-Ptest`, or `-Pprod` when building the JAR. The example packages the production configuration. Use the Oracle and JWT settings for the selected environment.
